Курсу нужны две вещи: **JDK 21** и **IntelliJ IDEA**. Ставьте **Community Edition** — бесплатной версии достаточно, **Ultimate не нужна**. VS Code для Java-части не используем: почему — в разделе [«Почему не Visual Studio Code»](#почему-не-visual-studio-code).

<Aside type="note" title="Короткая версия">
  Установите JDK 21, скачайте IntelliJ IDEA Community Edition, откройте папку `learn-java-core`, дождитесь Gradle Sync, откройте `HelloWorld.java` и нажмите зелёную стрелку рядом с `main`.
</Aside>

<Aside type="tip" title="Ultimate не нужна — это важно">
  **Community Edition полностью достаточно.** Не покупайте Ultimate, не оформляйте подписку и не ищите промокоды. В курсе не используются Spring, Jakarta EE, инструменты баз данных, HTTP Client, профайлер и поддержка JavaScript — то, за что просят деньги. Нужные Java, Gradle, JUnit, отладчик и Lombok есть в бесплатной версии.
</Aside>

<Aside type="caution" title="С 2025.3 у JetBrains один установщик">
  Community Edition больше не выходит отдельной загрузкой: теперь на сайте один **IntelliJ IDEA**, а её возможности остались в нём бесплатными. Платные функции Ultimate просто заблокированы без подписки. Если вы видите только одну кнопку Download — это и есть нужная версия, лицензия не требуется.
</Aside>

## 1. Установите JDK 21

Курс использует `record`, `var`, switch-выражения и Lombok. Формально хватит JDK 17+, но стабильнее всего всё работает на **JDK 21 (LTS)**.

Скачайте [Eclipse Temurin 21](https://adoptium.net/temurin/releases/?version=21) (Windows x64, установщик `.msi`) или [Amazon Corretto 21](https://aws.amazon.com/corretto/). В установщике Temurin включите **Add to PATH** и **Set JAVA_HOME variable** — так Gradle и терминал найдут JDK без ручной настройки.

После установки откройте **новое** окно терминала и проверьте версию:

```bash
java -version
```

В выводе должно быть что-то вроде `openjdk version "21.0.x"`. Если видите `1.8`, `11` или `17` — подхватился другой JDK: проверьте `PATH` и `JAVA_HOME`. Для Gradle нужен именно **JDK с компилятором**, а не JRE.

<Aside type="note" title="macOS и Linux">
  На macOS удобно поставить `brew install --cask temurin@21`, на Linux — пакет `temurin-21-jdk` из репозитория Adoptium. Проверка та же: `java -version`.
</Aside>

## 2. Установите IntelliJ IDEA Community Edition

Скачайте IDE с [jetbrains.com/idea/download](https://www.jetbrains.com/idea/download/).

1. На странице по умолчанию может быть выбран Ultimate. Найдите **Community Edition** и скачайте её. Если страница уже предлагает единый IntelliJ IDEA — скачивайте его, бесплатного режима достаточно.
2. Запустите установщик. Настройки по умолчанию подходят. Полезно включить **Create Desktop Shortcut** и **Add "bin" folder to the PATH** — появится ярлык и команда запуска из терминала.
3. При первом запуске выберите **Do not import settings**, тему на свой вкус и не устанавливайте лишние плагины.
4. Если появится окно с предложением 30-дневного триала Ultimate, соглашаться не обязательно. Для курса это не важно: когда триал закончится, IDE продолжит работать бесплатно, и все нужные функции останутся.

Проверить версию можно в **Help → About**: подойдёт и `IntelliJ IDEA Community Edition`, и просто `IntelliJ IDEA` без активированной подписки.

Что входит в бесплатную версию, а что является платным:

| Возможность | Бесплатно (Community) | Ultimate | Нужно в курсе |
| --- | --- | --- | --- |
| Java, Gradle, JUnit, отладчик, рефакторинги | да | да | да |
| Lombok | да, плагин встроен | да | да |
| Полная поддержка Spring и Jakarta EE | нет | да | нет |
| Инструменты баз данных и SQL | просмотр схемы | полный набор | нет |
| HTTP Client | нет | да | нет |
| Профайлер | нет | да | нет |
| Полная поддержка JavaScript и TypeScript | нет | да | нет |

Итог: для Java Core платить не за что. Всё, что встречается в уроках, работает в бесплатном режиме.

## 3. Откройте репозиторий

Склонируйте репозиторий или скачайте ZIP:

```bash
git clone https://github.com/baileyseye/learn-java-core.git
```

Без Git: на странице GitHub нажмите **Code → Download ZIP** и распакуйте архив.

1. В IntelliJ IDEA выберите **File → Open** (или **Open** на стартовом экране).
2. Укажите **корневую папку** `learn-java-core` — ту, где лежат `build.gradle.kts` и `gradlew.bat`. Не открывайте отдельно папку `src`.
3. Если появится запрос **Trust Project** — подтвердите.
4. Дождитесь **Gradle Sync**. При первом запуске Gradle 8.13 скачается автоматически; отдельно устанавливать Gradle не нужно.
5. Проверьте JDK: **Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JVM** → JDK 21. Затем **File → Project Structure → Project** → SDK 21 и **Language level** 21.

Если Sync падает с ошибкой про `JAVA_COMPILER` или JRE, значит Gradle нашёл JRE вместо JDK. Решение — в таблице в конце страницы.

## 4. Запустите первый пример

Откройте файл:

```text
src/main/java/org/baileyseyes/_1/__start_from_here__/HelloWorld.java
```

Дождитесь окончания индексации. Рядом с `public static void main` появится зелёная стрелка. Нажмите её и выберите **Run 'HelloWorld.main()'**. Если конфигурация уже выбрана, достаточно `Shift+F10`.

В панели **Run** внизу появится:

```text
Hello World
```

Если зелёной стрелки нет, проверьте, что файл лежит в `src/main/java`, проект синхронизирован и выбран SDK. В большинстве случаев помогает правый клик по файлу → **Run 'HelloWorld.main()'**.

Поздравляем — вы запустили первую программу курса. Дальше переходите к [уроку 1](../../lessons/hello-world/).

## 5. Проверьте сборку

Этот шаг не обязателен, но помогает убедиться, что настроено всё: компилируются все примеры, а не только `HelloWorld`. Из корня репозитория выполните:

```bash
.\gradlew.bat build
```

На macOS и Linux команда другая:

```bash
./gradlew build
```

Первый запуск дольше обычного: скачиваются Gradle и зависимости. Если появляется ошибка про `JAVA_COMPILER` или `jre`, вернитесь к шагу 1 — Gradle взял JRE вместо JDK.

## 6. Запустите сайт курса (необязательно)

Сайт — отдельный фронтенд на Astro. Он нужен, если вы хотите читать уроки локально или менять их; Java-часть от него не зависит. Понадобится Node.js 22+.

```bash
npm install
npm run dev
```

Адрес появится в консоли: `http://localhost:4321/learn-java-core/`.

В IntelliJ IDEA уже есть готовые конфигурации в папке `.run/`. Выберите **Frontend: dev** и нажмите **Run**. Если IDE попросит Node interpreter, укажите путь к `node.exe` — дальше настройка сохранится в проекте.

В бесплатной версии нет полноценной поддержки JavaScript и Astro, поэтому файлы сайта будут открываться почти как обычный текст. Если планируете много править сайт, для этого удобнее VS Code — но только для сайта, не для Java.

## Почему не Visual Studio Code

Короткий ответ: **VS Code — не Java-IDE, а редактор, который становится Java-IDE только после установки и настройки расширений.** Для Python такой фокус проходит, для Java — нет: слишком многое зависит от того, как редактор понял Gradle-проект.

<Aside type="danger" title="Java-часть в VS Code не поддерживается">
  Если вы запускаете уроки в VS Code и что-то не работает, невозможно отличить ошибку в коде от ошибки настройки расширений. В IntelliJ IDEA такие проблемы всплывают на этапе Gradle Sync и подсвечиваются понятнее.
</Aside>

Причины, по которым курс сознательно не использует VS Code:

- **Java не работает из коробки.** Нужно поставить Extension Pack for Java, разобраться с JDK, импортом Gradle и classpath. В IntelliJ IDEA всё это уже есть после установки.
- **Gradle и Lombok — главный источник боли.** Курс использует Lombok, и в VS Code его нужно отдельно подключать и настраивать annotation processing. Иначе `@Getter`, `@Setter` и `@Builder` подсвечиваются как ошибки, хотя код правильный.
- **Ошибки выглядят одинаково.** `Cannot resolve symbol` может означать и опечатку в коде, и неправильно импортированный проект. Новичок начинает чинить код, хотя проблема в редакторе. В IDEA есть понятная точка отсчёта: Gradle Sync прошёл, SDK выбран, зелёная стрелка работает.
- **Инструкции курса не совпадут.** Скриншоты, горячие клавиши (`Shift+F10`, `Ctrl+Alt+L`, `psvm`, `sout`) и конфигурации запуска рассчитаны на IntelliJ. В VS Code вы будете переводить инструкции вместо того, чтобы учить Java.
- **Запуск и отладка требуют лишних шагов.** В VS Code запуск `main` зависит от расширения и импорта проекта. В IDEA достаточно нажать стрелку рядом с методом — одинаково у всех учеников.
- **Это ещё и рабочий навык.** IntelliJ IDEA — стандарт в Java-индустрии. Научиться в ней работать полезно само по себе, а Community Edition для этого бесплатна.

Сравнение по делу:

| Критерий | VS Code | IntelliJ IDEA Community |
| --- | --- | --- |
| Java, Gradle, JUnit | через расширения | из коробки |
| Lombok | отдельный плагин и настройка | встроен |
| Импорт Gradle-проекта | расширение, свои ошибки | штатный Gradle Sync |
| Запуск `main` | через расширение или конфиг | зелёная стрелка |
| Инструкции курса | не совпадают | совпадают |
| Цена | 0 | 0 |

При этом VS Code не запрещён вообще. Он отлично подходит для сайта: `.astro`, CSS, Markdown, `npm run dev`. Если вы уже уверенно настраиваете Java в VS Code, технически примеры запустятся. Но на старте это лишний слой проблем: вы будете отлаживать не Java, а редактор.

Правило курса простое: **Java — в IntelliJ IDEA, сайт и тексты — в любом удобном редакторе.**

## Если что-то не работает

| Симптом | Что проверить |
| --- | --- |
| `java -version` показывает 1.8, 11 или 17 | Подхватился другой JDK. Установите JDK 21 и проверьте `PATH` и `JAVA_HOME` |
| `Toolchain installation ... does not provide ... JAVA_COMPILER` | Gradle взял JRE вместо JDK. Укажите JDK 21 в **Gradle JVM** |
| `class file has wrong version` или `invalid target release` | Project SDK, Language level и Gradle JVM должны быть 21 (минимум 17) |
| Gradle Sync не завершается | Проверьте интернет, прокси и JDK 21. Отдельный Gradle не нужен — используется wrapper 8.13 |
| `Cannot resolve symbol` у своих классов | Открыта не корневая папка, проект не синхронизирован или не выбран SDK |
| `@Getter`, `@Setter`, `@Builder` красные | Включите annotation processing и плагин Lombok, затем **Reload All from Disk** |
| Нет зелёной стрелки у `main` | Файл вне `src/main/java`, проект не собран или неверный SDK. Попробуйте правый клик → **Run** |
| Сайт не собирается | Нужен Node.js 22+, затем `npm install` и `npm run dev` |
| Порт 4321 занят | Astro предложит другой порт — смотрите адрес в консоли |

<Aside type="tip" title="Полезные горячие клавиши">
  `Shift+F10` — запустить, `Shift+F9` — запустить с отладчиком, `Ctrl+B` — перейти к объявлению, `Ctrl+Alt+L` — отформатировать код, `psvm` + Tab — вставить `main`, `sout` + Tab — вставить `System.out.println`, `Ctrl+Space` — подсказки, `Double Shift` — поиск везде. В блоках «Практика» курса `Ctrl+Enter` запускает проверку, а `Ctrl+Space` открывает подсказки по коду.
</Aside>
